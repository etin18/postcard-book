# 明信片通訊錄

出國寄明信片時，不用再到處翻大家的地址。打個名字就查到地址，寄完順手記一筆，
回家還能看到這些年寄過哪些明信片給誰。

- **前端**：純 HTML / CSS / JS，無框架、無建置步驟
- **後端**：Google Apps Script（免費、免主機、免登入設定）
- **資料**：存在你自己的 Google 試算表
- **照片**：明信片照片壓縮後只存在手機本機（IndexedDB），不上傳
- **離線可用**：通訊錄整份存在手機，人在國外沒訊號照樣查得到地址

完整的功能設計在 [需求規格.md](需求規格.md)。

## 設定步驟（第一次，約 10 分鐘）

### 第 1 步：建立試算表並貼上後端程式

1. 開一個新的 [Google 試算表](https://sheets.new)
2. 上方選單 **擴充功能 → Apps Script**
3. 把左邊預設的 `Code.gs` 內容整份刪掉，貼上本專案
   [`google-apps-script/Code.gs`](google-apps-script/Code.gs) 的全部內容
4. **設定通關密語（重要）**：找到最上方這一行，把引號裡改成你自己的一組密語：
   ```js
   var SECRET = '';   // ← 改成你自己的通關密語，例如 'postcard2026kk'
   ```
   例如改成 `var SECRET = 'postcard2026kk';`。這組密語等於資料的鑰匙，之後要填進 App。
5. 按上方的 **儲存**（磁片圖示）

> 資料表（「朋友」「明信片」兩張）會在第一次使用時自動建立，你不用手動開。
>
> ⚠️ 你在這裡改的密語是貼在「你自己的」Apps Script 裡，只存在 Google 端。
> **請不要**把含有真實密語的 `Code.gs` 貼回 GitHub 或公開出去 —— 公開 repo 裡的版本
> 永遠保持 `SECRET = ''`（空的）。

### 第 2 步：部署成網頁應用程式

1. 右上角 **部署 → 新增部署作業**
2. 齒輪圖示選 **網頁應用程式**
3. 設定：
   - **說明**：隨意（例如「明信片 v1」）
   - **執行身分**：**我**
   - **具有存取權的使用者**：**任何人** ← 這項一定要選「任何人」，App 才連得上
4. 按 **部署**，第一次會跳出授權，依指示允許（會出現「Google 尚未驗證這個應用程式」，
   點 **進階 → 前往「未驗證」的專案**，那是你自己寫的程式，安全）
5. 複製產生的 **網頁應用程式網址**，結尾長這樣：
   `https://script.google.com/macros/s/AKfy……/exec`

### 第 3 步：把網址貼進 App

1. 用手機瀏覽器打開 App（見下方「怎麼開 App」）
2. 點右上角的 **齒輪** → **Google 試算表連線**
3. 貼上剛剛的網址，並在下面填入第 1 步設定的**通關密語**（要一模一樣）
4. 按 **儲存並測試**，看到「連線成功（密語已啟用）」就完成了

之後每次操作都會自動同步，不用再設定。

## 怎麼開 App

因為 App 需要透過網址（http/https）打開，直接雙擊 `index.html` 是不行的
（Service Worker、相機、IndexedDB 都需要正式網址）。兩種方式擇一：

### 方式 A：免費靜態空間（推薦，手機隨時能開）

把 `www/` 資料夾丟到任一免費靜態網站服務，得到一個網址：

- **Cloudflare Pages** / **Netlify** / **Vercel** / **GitHub Pages** 都可以，拖曳 `www` 上傳即可
- 例：Netlify 直接把 `www` 資料夾拖進 <https://app.netlify.com/drop>，幾秒就有網址

拿到網址後在手機瀏覽器打開，即可使用。

### 方式 B：本機測試（電腦上先看看）

```bash
cd www
python3 -m http.server 8788
```

瀏覽器開 <http://localhost:8788>。（本機 localhost 相機、Service Worker 也能運作。）

## 使用說明

App 只有兩個分頁。

### 寄明信片

站在郵局櫃檯時就用這一頁，從頭到尾一頁做完：

1. **打名字找地址** —— 最上面的搜尋框，中文名、英文收件人名、城市、國家都能搜
2. **點一下展開** —— 完整地址用大字顯示，照著抄就好；旁邊的 **複製地址** 可以整段拷走
3. **往下順手記一筆** —— 展開後下面就是寄送欄位：從哪個國家寄、日期、備註、拍照，
   按 **記下這張明信片** 完成。存完搜尋框會自動清空，可以直接查下一個人

- **新增朋友**：右下角 ＋。搜尋不到某個人時，結果區也會直接出現「＋ 新增這個朋友」
- **編輯／刪除**：展開後點 **編輯**
- **朋友搬家了**：在編輯畫面改成新地址，然後按下方的 **他搬家了 · 保留舊地址並新增**。
  舊地址會標成「已搬家」留在歷史裡（展開時看得到「以前住過」），不會被蓋掉

### 寄信歷史

一份依日期排序的清單，加上一排可以疊加的篩選器：

- **朋友** —— 選一個人，就看到寄給他的全部，等於「我寄過幾張給他」
- **國家**
- **日期區間** —— 要回顧某一趟旅行就拉那段日期，跨國的旅行照樣一次看完
- **只看還沒收到的** —— 挑出對方還沒收到的

卡片右邊的圓圈可以直接勾「已收到」，點卡片本身則是編輯或刪除。有照片的會顯示縮圖，
點縮圖看大圖。

### 設定

右上角齒輪。裡面有試算表連線、照片佔用空間、資料統計，以及匯出 CSV
（通訊錄和寄信紀錄分開匯出；寄信紀錄匯出的是**目前篩選後**的內容）。

## 安全性

**這裡面是朋友的住家地址，請當成密碼等級的資料保管。**

- **程式碼公開沒關係**：這個網頁是純前端，連到你試算表的鑰匙（Apps Script 網址 + 通關密語）
  存在你手機裡，**不在** GitHub 的程式碼裡。別人打開你的公開網址，看到的是一個沒連到
  任何資料的空殼。
- **兩把鑰匙缺一不可**：要動你的資料，得同時知道「網址」和「通關密語」。網址不公開、
  密語只在你腦中與手機裡，就是安全的。
- **不要外流**：不要把網址或密語貼到公開群組；截圖分享 App 畫面時，記得遮掉地址和設定頁。
- **萬一外洩**：改 `Code.gs` 的 `SECRET` 換一組密語（舊密語立刻失效），或到 Apps Script
  重新部署換網址。

### 幾個要知道的點

- **離線查得到地址**：通訊錄整份快取在手機，人在國外沒網路照樣搜尋、照樣看地址。
  新記的明信片會先存手機，狀態列顯示「待同步」，一有網路自動補送。
- **照片只在本機**：清除瀏覽器資料或換手機，照片會不見，但**地址和寄信紀錄在試算表裡是
  安全的**。設定頁可看照片佔用空間。
- **搬家歷史不會消失**：標記搬家後舊地址仍留在試算表裡（狀態欄是「已搬家」），
  只是搜尋時不會出現。
- **刪除朋友不會刪掉寄信紀錄**：紀錄裡存了當時的名字，所以歷史仍然完整。
- Apps Script 免費版每次請求有 1～3 秒延遲屬正常，App 已做本機快取，開啟不會等。

## 開發

```bash
node scripts/make-icons.js      # 重新產生 PWA 圖示

# 版面實測（需要本機 server 開在 8788）
cd www && python3 -m http.server 8788 &
PW_CORE=<playwright-core 路徑> node scripts/screenshot.js
```

## 之後想包成 APK

現在這個 PWA「加到主畫面」其實已經很接近 App 體驗。若日後真的要一個可安裝的
`.apk` 檔，最省事的路是用 [Capacitor](https://capacitorjs.com/) 把 `www/` 直接包起來：

```bash
# 需先安裝 JDK 17 與 Android SDK
npm init -y
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init 明信片通訊錄 com.example.postcardbook --web-dir=www
npx cap add android
npx cap sync
cd android && ./gradlew assembleDebug
# APK 產出在 android/app/build/outputs/apk/debug/app-debug.apk
```

`www/` 這份程式不用改，Capacitor 會原封不動包進去。需要時再處理即可。
